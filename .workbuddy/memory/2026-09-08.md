## 服务器选型评估
- 目标机器：阿里云 ECS 经济型 e / 2vCPU / 4GiB / 60GiB ESSD Entry
- 结论：blogProject 单独部署够用（常驻约 1.4–1.7GB）；Memora（F:\goland\agentProject\Memora）
  因 Docling+OCR 单独跑就吃 3.3–4GB，2C4G 勉强；两者同机必须上 2C8G。
- 关键建议：镜像在 CI 构建，ECS 只 pull；4GiB 机器必配 2GB swap。

## 搭建 CI/CD 流水线（GitHub Actions + 阿里云 ACR + ECS）
新增文件：
- `.github/workflows/ci.yml`：push/PR 触发。后端 go vet + gofmt + go test -race + build；
  前端 npm ci + vue-tsc + vitest + build；docker 作业校验 compose 语法并试构建两个镜像。
- `.github/workflows/cd.yml`：workflow_run 监听 CI，仅 CI 成功才部署（门禁）。
  tag 用 commit sha，构建推 ACR，SCP 同步 compose+脚本，SSH 执行 deploy.sh。
- `docker-compose.prod.yml`：生产编排，用 ACR 镜像而非本地构建，并为每个服务设 mem_limit
  （mysql 1g / ollama 1g / minio 512m / backend 512m / frontend 128m / redis 256m）。
- `scripts/deploy.sh`：pull → up -d → 健康检查（/api/v1/health 与 /）→ 失败自动回滚上一 tag。
- `scripts/setup-server.sh`：装 Docker、配镜像加速、建 2GB swap、建 /opt/blog。
- `.env.example`、`docs/CI-CD.md`（含 Secrets 清单、排错表、简历技术点）。

## 修复的既有问题
- `vue/src/components/NavBar.vue` 与 `vue/src/views/HomeView.vue`：
  `route.query.q` 类型为 `string | string[]`，导致 vue-tsc 报 TS2322，`npm run build` 会失败。
  已改为 `(Array.isArray(q) ? q[0] : q) || ''`。
- `.gitignore` 缺 `.env`，已补上（否则有泄露真实密码风险）。

## 重要坑（务必记住）
- **本仓库 Go 源码全是 CRLF 换行**，而 gofmt 只认 LF。直接 `gofmt -l .` 会误报上百个文件。
  CI 里已改为先 `sed 's/\r$//'` 剥离 CR 再 diff，只报真实格式问题。
  彻底修需加 `.gitattributes`（`*.go text eol=lf`）+ `git add --renormalize .`，未做，避免大范围改动。
- `utils.ParseTime` 基于 `time.Parse`，返回的是 **UTC** 时间，与本地时区无关，测试已锁定该语义。
- **`vue/dist` 被 git 跟踪**（构建产物入库）。本地跑 `npm run build` 会污染工作区，
  结束后需 `git checkout -- vue/dist` 并 `git clean -fd vue/dist` 还原。建议后续把 dist 移出版本库。
- 本地 Windows 无 cgo，`go test -race` 跑不了，只能在 Linux CI 上执行。
