## 服务器选型评估
- 目标机器：阿里云 ECS 经济型 e / 2vCPU / 4GiB / 60GiB ESSD Entry
- 结论：blogProject 单独部署够用（常驻约 1.4–1.7GB）；Memora（F:\goland\agentProject\Memora）
  因 Docling+OCR 单独跑就吃 3.3–4GB，2C4G 勉强；两者同机必须上 2C8G。
- 关键建议：镜像在 CI 构建，ECS 只 pull；4GiB 机器必配 2GB swap。

## 关键修复：阿里云 ACR 个人版不接受 OCI 证明清单
- 报错：`denied: unknown manifest class for application/vnd.oci.empty.v1+json`（推送 blog-backend:309c16a 时）
- 原因：build-push-action/Buildx 默认附加 provenance + SBOM 证明清单，ACR 个人版不支持该 OCI 媒体类型。
- 修复：在 `cd.yml` 两个 build-push-action 步骤加 `provenance: false` 与 `sbom: false`。
- 已同步写入 `docs/CI-CD.md` 排错表。以后给任何阿里云 ACR 个人版写构建推送都要默认带上这两行。

## 关键修复：后端容器 panic「Config File "config" Not Found」
- 现象：CD 的镜像构建/推送全绿，但部署后健康检查失败并回滚；后端日志
  `panic: 应用初始化失败: 加载配置失败: Config File "config" Not Found in "[/app/configs /app]"`。
- 根因：`blog/configs/config.yaml`（含真实密码）被 .gitignore 排除，GitHub Actions 的构建上下文里
  只有 `config.yaml.example`，Dockerfile `COPY configs` 后镜像内没有 config.yaml，viper 找不到就 panic。
- 修复（配置与镜像分离，12-Factor）：
  1. `blog/.dockerignore` 改为只排除 `configs/config.yaml`、`configs/config2.yaml`（模板保留进镜像）。
  2. `blog/Dockerfile` 加兜底：`[ -f config.yaml ] || cp config.yaml.example config.yaml`，保证镜像自身可启动。
  3. `docker-compose.prod.yml` 后端加 `./configs/config.yaml:/app/configs/config.yaml:ro`，
     并补齐 CORE_COACH_* / MYSQL_PASSWORD / JWT_SECRET / MINIO_* 等环境变量覆盖。
  4. `docker-compose.yml`（本地开发）同步加挂载 `./blog/configs/config.yaml`，否则本地构建会丢配置。
  5. `scripts/deploy.sh` 加前置校验（缺配置文件在拉镜像前就 fail）+ 失败时打印后端 50 行日志。
  6. `cd.yml` 新增「镜像冒烟测试」步骤：docker run 自检二进制与配置文件是否存在，把问题挡在部署前。
- 经验：镜像构建成功 ≠ 能启动。CD 必须有「推送后、部署前」的冒烟自检环节。
- 运维要点：服务器上 `/opt/blog/configs/config.yaml` 需手动放置（密钥不进镜像不进 git）。
